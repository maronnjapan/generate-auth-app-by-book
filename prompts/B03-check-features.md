# B.3 既存の実装に含まれる機能の確認

## 目的

今の実装に、どの仕組みが入っているかを把握したい。特に PKCE（RFC 7636）の有無を知りたい。
次の作業（PKCE を使わない比較用の構成を作る）に備えるため、変更が必要になる箇所も知りたい。

## 対象

- `chapter2/openid-provider/`（OpenID Provider）
- `chapter2/app-a/`、`chapter2/app-b/`（Web アプリ）

## 依頼

コードは変更しないでください。読んで報告するだけにしてください。

次の項目を表にまとめてください。各行に、根拠となるファイルと行番号を示してください。

1. PKCE: 認可エンドポイントで `code_challenge` と `code_challenge_method` を受け取り、認可コードと一緒に保存しているか。トークンエンドポイントで `code_verifier` を受け取り、検証しているか。アプリ側で `code_verifier` を生成し、`code_challenge` を送り、交換時に `code_verifier` を送っているか。無ければ「無し」と書く
2. クライアント認証: トークンエンドポイントが受け付ける方式（`client_secret_post`、`client_secret_basic`、なし）と、検証の内容
3. 認可コード: 一回限りか、有効期限、`redirect_uri` の一致確認、`client_id` の一致確認、保存場所
4. `state` と `nonce`: アプリ側の生成、保存、検証の有無。OP 側の `nonce` の扱い（ID トークンに載せているか）
5. セッション: OP のセッション Cookie の名前、属性（HttpOnly、SameSite、Secure）、有効期限。アプリのセッションも同様
6. ID トークン: 署名アルゴリズム、含まれるクレーム、アプリ側で検証している項目（署名、`iss`、`aud`、`exp`、`nonce`）
7. 依頼していないのに実装されている機能、依頼したのに省かれている機能

## 出力

- 表（項目、現在の実装、根拠のファイル:行、備考）
- PKCE の有無を一言で結論
- 次に「PKCE を使わない比較用の構成」と「トークン交換の前に止める検証モード」を作るときに、変更が必要になる箇所の一覧（ファイルと関数名）

- 回答は日本語で書く
